  <name>Task 3: Add pure similarity retrieval to MemoryStore</name>
  <files>src/agentic/memory_store.py</files>
  <action>
Add a new retrieval method that uses pure similarity without coherence weighting:

**Design note (from CONTEXT.md):** The ROADMAP mentions "weighted by embeddedness/connections" but
this was refined during phase discussion. Per CONTEXT.md: "Remove embeddedness from explicit
weighting — connectivity naturally affects retrieval through network pathways" and "Pure similarity
(bit overlap) as primary retrieval mechanism". Well-connected patterns surface naturally through
the connection network; explicit embeddedness weighting is not needed. This is the correct semantic.

1. Add new method `retrieve_pure_similarity()`:
```python
def retrieve_pure_similarity(
    self,
    query: str,
    top_k: int = 10,
    use_evolved: bool = True,
    recency_boost: float = 0.0,  # 0.0 = no boost, 0.1 = 10% weight
) -> list[RetrievalResult]:
    """Retrieve using pure similarity - coherence does NOT affect ranking.

    This is the Phase 3 semantics where coherence = malleability, not accessibility.
    Low-coherence (crystallized) patterns are just as retrievable as high-coherence.

    Args:
        query: Query text.
        top_k: Number of results.
        use_evolved: Use evolved bits (with acquired).
        recency_boost: Optional recency factor (0-1). If >0, score =
            (1-boost)*similarity + boost*recency_factor.
    """
```

2. Implementation:
   - Advance tick, decay all patterns (same as existing retrieve)
   - Create query pattern
   - For each pattern: compute pure Jaccard similarity
   - Optional recency: recency_factor = 1.0 / (1.0 + (current_tick - last_access_tick))
   - Combine: score = (1-recency_boost)*jaccard + recency_boost*recency_factor
   - Sort by score descending, take top_k
   - Refresh retrieved patterns (apply_refresh with score)
   - Return results

3. Keep existing retrieve() method for backward compatibility but add deprecation comment suggesting retrieve_pure_similarity() for Phase 3 semantics.

4. Update retrieve_with_surprise() to optionally use pure similarity:
   - Add parameter `use_pure_similarity: bool = False`
   - If True, use retrieve_pure_similarity internally instead of _retrieve_interference
   - This allows testing the new semantics with surprise detection
  </action>
